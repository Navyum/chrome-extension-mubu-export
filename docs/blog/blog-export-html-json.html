幕布导出HTML/JSON：可视化归档与二次处理指南

7分钟 2026年7月2日 小林 · 数据归档指南

幕布导出 HTML 和 JSON 的价值不一样：HTML 让人看，JSON 留给机器和未来的你。HTML 适合打开即读、打印、发给别人预览；JSON 则保留幕布原始节点树，适合做长期备份、版本管理和自定义转换。

很多用户只知道导出 Markdown 或 PDF，却忽略了 HTML/JSON 这两个格式。它们不一定是每天最常用的格式，但在数据迁移和归档里很关键：HTML 保留视觉结构，JSON 保留底层结构。两份一起存，后续选择空间会大很多。

结论先说：想把幕布笔记保存成可阅读网页，选 HTML；想保留原始节点、备注、图片字段、折叠状态，选 JSON。需要严肃备份时，建议同时导出 Markdown、HTML、JSON 三份：Markdown 迁移，HTML 查看，JSON 兜底。

HTML 和 JSON 怎么选？

需求推荐格式理由
以后直接打开阅读HTML浏览器即可打开，保留大纲样式和备注
打印或转 PDFHTML适合走浏览器打印流程
保留幕布原始结构JSON节点树、备注和状态字段更完整
写脚本转换成自定义格式JSON比从 Markdown 反解析更可靠
迁移到 Obsidian / NotionMarkdown目标工具兼容性最好

如果你不是开发者，也可以导出 JSON。你现在不一定会打开它，但它相当于一份更接近幕布内部结构的备份。以后如果工具变了、需求变了，JSON 的可转换空间通常比 PDF/Word 更大。

如何批量导出幕布为HTML？

  1. 先在 Chrome 里登录 幕布网页版。
  2. 打开「幕布导出工具」插件。
  3. 点击「获取文件信息」，等待文件夹和文档扫描完成。
  4. 导出格式选择 HTML (.html)。
  5. 点击「开始导出」。

导出的 HTML 文件会按幕布文件夹结构保存。每篇幕布文档对应一个 .html 文件，双击即可在浏览器中打开。插件会尽量保留幕布节点层级、备注、表格、图片引用和基础样式，并为公式渲染预留能力。

HTML 归档有哪些边界？

HTML 很适合「人类可读归档」，但它不等于百分百离线包。当前插件生成的 HTML 里，正文文本、节点结构和样式在本地文件中；文档图片通常仍然引用幕布图片地址；公式渲染也可能依赖外部资源。也就是说，只要你未来还能访问对应资源，页面体验会更完整。

如果你要做长期离线备份，建议这样处理：

  • HTML 用来快速查看和打印。
  • JSON 用来保留原始结构。
  • 重要图片另外手动归档，或后续写脚本从 JSON/HTML 中提取图片链接批量下载。

对大多数纯文本笔记来说，HTML 已经足够好用；对大量图片、公式、表格的资料库来说，HTML + JSON 才更稳。

如何批量导出幕布为JSON？

JSON 的导出步骤和 HTML 一样，只需要在格式下拉框中选择 原始结构 (.json)。导出的文件是格式化后的幕布 definition 数据，适合直接交给脚本、编辑器或版本管理系统处理。

一份 JSON 通常会包含这些信息：

  • nodes：文档的大纲节点树。
  • text：节点文本，通常包含幕布编辑器生成的 HTML 片段。
  • note：备注内容。
  • children：子节点数组。
  • collapsed：节点是否折叠。
  • completed：节点是否完成。
  • image / images：图片相关字段和链接。

这也是为什么 JSON 很适合「兜底备份」。如果未来你想把幕布内容转成某个新工具需要的格式，从 JSON 开始写转换脚本，会比从 PDF 或 Word 里抽取内容可靠得多。

HTML/JSON 和 Markdown 有什么关系？

Markdown 是迁移的首选格式，因为 Obsidian、Notion、飞书、GitHub 都更容易接收 .md 文件。但 Markdown 是一个转换结果，不是幕布的完整原始数据。为了让它通用，插件会把幕布节点转换成列表、标题、引用块和表格等 Markdown 表达。

HTML 和 JSON 则分别补上 Markdown 的两个短板：

格式优势短板
Markdown跨工具迁移最方便无法完整表达所有幕布状态
HTML视觉还原度高，适合阅读不适合机器二次处理
JSON结构最完整，适合脚本处理普通用户直接阅读不方便

所以最佳实践不是三选一，而是按用途组合。迁移用 Markdown，归档看 HTML，兜底留 JSON。

适合开发者的二次处理思路

如果你会写一点脚本，JSON 可以做很多事：

  • 统计每个文件夹下的文档数量和字数。
  • 提取所有带图片的节点，生成图片下载清单。
  • 把完成状态转换为任务列表。
  • 把某些标签或关键词提取为知识库索引。
  • 根据文件夹路径生成 Hugo、Hexo 或 Docusaurus 的内容目录。

这些需求如果从 PDF 做，几乎不可维护；从 Word 做，会遇到格式噪音；从 Markdown 做，可以但会丢掉一些幕布特有字段。JSON 不是给所有人每天看的，但它是最适合留给自动化流程的格式。

推荐的归档目录结构

建议在插件设置页把下载子目录设成带日期的路径，例如：

MubuBackup/2026-07

然后按格式导出多轮：

MubuBackup/2026-07/Markdown/
MubuBackup/2026-07/HTML/
MubuBackup/2026-07/JSON/

当前插件的设置页支持自定义下载子文件夹。每轮导出前改一次子目录，就能把不同格式分开放，后续同步到网盘、NAS 或 Git 仓库都会清晰很多。完整的备份频率建议可以参考幕布数据备份策略。

常见问题

HTML 是否比 PDF 更适合备份？

取决于目标。PDF 更适合定稿阅读和发送给别人，HTML 更适合自己归档、搜索和打印。HTML 文件还能用浏览器查看源码，后续处理空间比 PDF 大。

JSON 能直接导入其他笔记软件吗？

通常不能直接导入。JSON 是幕布原始结构备份，不是通用笔记格式。如果要导入 Obsidian、Notion、飞书，优先用 Markdown；如果要导入自研系统或做批量转换，再从 JSON 写脚本。

导出 HTML/JSON 会修改幕布原文档吗？

不会。插件只读取文档数据并在本地生成文件，不会修改、删除或上传你的幕布内容。所有导出的文件都保存到你本机的浏览器下载目录。
