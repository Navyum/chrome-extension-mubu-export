# 幕布里存了500篇笔记，我花了一个周末把它们全部「救」了出来

本文首发于「效率工具指南」

文/安哥拉

Hello 大家好，我是安哥。

今天想和大家聊一件让我又爱又恨的事——我在幕布里存了将近四五年的笔记，从读书摘录、项目复盘到每周的会议纪要，零零总总加起来有 500 多篇。直到上个月我决定把一部分内容迁移到 Obsidian 做本地知识库时，才发现：**把自己的数据从幕布里完整拿出来，远比想象中困难。**

## 01. 为什么要导出？

先说说我的场景。我并不是要「逃离」幕布——幕布的大纲编辑体验依然是我用过最顺手的。但作为一个经历过某云笔记「会员涨价+限制设备数」事件的人，我对所有在线工具都养成了一个习惯：**定期把数据备份到本地。**

另一方面，我最近在用 Obsidian 搭建自己的第二大脑，需要把幕布里的一些方法论笔记迁移过去。Obsidian 原生吃 Markdown，所以我需要的是 `.md` 格式的文件。

## 02. 官方导出有多难用？

幕布目前支持的导出格式有：Word、PDF、图片、HTML、OPML 和 Freemind。

注意看，**没有 Markdown。**

![幕布官方支持的导出格式](https://mubu.toolab.top/images/feat1.webp)

更让人头疼的是导出流程：你必须逐篇打开文档，点右上角菜单，选择导出格式，等待生成，然后下载。500 篇文档意味着重复这个流程 500 次。

我粗略算了一下，每篇平均 30 秒，500 篇就是 250 分钟，超过 4 个小时的纯机械操作。这还没算上中途可能遇到的加载失败、网络超时……

## 03. 我试过的「弯路」

**方案一：OPML 转 Markdown**

网上搜了一圈，最常见的建议是：先把幕布文档导出为 OPML 格式，再用命令行工具 `opml-to-markdown` 转换。

我试了。确实能转，但问题一大堆：
- 导出 OPML 本身也是逐篇操作，批量问题没解决
- 转换后的 Markdown 层级标记不太对，嵌套列表格式混乱
- 文档里的备注信息（幕布的「笔记」功能）在 OPML 中直接丢失了
- 图片链接全部丢失

**方案二：市面上的导出插件**

后来发现了一款叫 Mubu Dumper 的浏览器插件，XMind 团队出品。我满怀期待装上之后：

- 只支持 Markdown 和 XMind 两种格式
- 导出 Markdown 的时候直接卡死了（讽刺的是导出自家 XMind 格式倒是很流畅）
- 没有进度提示，不知道跑到哪里了
- 失败了没有重试机制，只能从头再来

折腾了整个下午，我的 500 篇笔记还是安静地躺在云端，纹丝不动。

## 04. 最终方案：一款真正好用的批量导出插件

后来在 GitHub 上偶然发现了一个开源项目——**Mubu Exporter**，试了一下，居然完美解决了我所有的痛点。

**安装过程（3分钟）：**

1. 从 Chrome 应用商店直接安装（搜索「幕布导出工具」）
2. 打开 mubu.com 保持登录
3. 点击插件图标，界面就出来了

**使用体验：**

点击「获取文件信息」，插件会自动扫描我所有的文件夹和文档——几秒钟后显示：527 篇文档，38 个文件夹。

选择导出格式为 Markdown，点击「开始导出」。

![批量导出进度界面](https://mubu.toolab.top/images/feat2.webp)

然后就是见证奇迹的时刻了：

- 进度条实时跳动，能看到正在处理第几篇
- 导出速度大概每秒 1-2 篇，全程不到 10 分钟
- 中途有 3 篇因为网络波动失败了，点了下「重试」按钮，秒过
- 导出的文件自动按照幕布的文件夹结构保存，不用我手动整理

打开导出的 Markdown 文件检查了一下：

- 大纲层级完美还原为无序列表嵌套
- 备注内容转换为引用块（`>`）
- 文件夹结构和幕布上一模一样

## 05. 几个让我惊喜的细节

除了核心的批量导出功能，这个插件有几个细节让我觉得作者是真的在「用心做工具」：

**多格式支持**：除了 Markdown，还支持 OPML、Freemind（.mm）、HTML、JSON。OPML 可以直接导入 XMind 和 Logseq，HTML 可以当静态备份页分享给别人。

**暂停和恢复**：导出过程中临时有事可以暂停，回来继续，不用从头开始。甚至浏览器意外关闭了，重新打开还能接着上次的进度继续。

**性能面板**：设置页里能看到每个文件的导出耗时、最慢的 TOP10 文件。对于排查问题很有帮助。

![设置与性能监控面板](https://mubu.toolab.top/images/feat3.webp)

**纯本地运行**：所有数据直接从幕布 API 拉取到本地，不经过任何第三方服务器。对于在意数据安全的人来说，这一点很重要。

![数据安全，本地执行](https://mubu.toolab.top/images/feat4.webp)

## 06. 导出后我做了什么

拿到 500 多个 Markdown 文件后，我做了这些事：

1. 直接把整个文件夹拖进 Obsidian 的 vault 目录，所有笔记立刻可以被全文检索和双向链接
2. 挑选了几篇方法论相关的文档发到了飞书知识库，供团队参考
3. 用 Git 做了版本管理，以后每个月跑一次导出，增量备份

整个过程从安装插件到完成迁移，大概花了 20 分钟。比起我之前折腾了整个下午还颗粒无收，这个效率提升是质的飞跃。

## 写在最后

我一直觉得，好的工具应该让你「用完即走」，而不是把你的数据锁在里面。幕布的编辑体验很好，但在数据导出这件事上确实还有进步空间。

好在社区总有人愿意用技术填补这些空白。如果你也是幕布的深度用户，建议趁现在把数据备份一份到本地——不是因为幕布不好，而是给自己的知识资产多买一份保险。
