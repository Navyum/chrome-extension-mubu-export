# 里程碑 2 手动验收

## 真实 Chrome 扩展

1. 执行 `npm test` 和 `npm run build`。在 `chrome://extensions` 中启用开发者模式，加载项目的 `dist/`，已有安装则点击重新加载。使用已登录幕布的同一浏览器配置文件。
2. 准备少量可用于测试的文档：根目录文档、两个文件夹、子文件夹、空文件夹，以及同名文件夹。不要把真实凭证或私人正文复制到日志、截图或问题报告。
3. 在弹窗点击“获取文件信息”，再点击“选择导出内容”。确认打开独立扩展页面，文件夹层级、总数正确。同名文件夹应分别显示，不能混为一个节点。
4. 勾选父文件夹，检查全部后代选中；取消一个子文档，检查父文件夹半选。跨文件夹选择单篇，检查已选数。检查全选、清空及空选择禁用开始按钮。
5. 等待“草稿已保存”，关闭并重新打开选择页。确认勾选恢复。大量文档的目录默认折叠，展开后每批最多 100 个兄弟节点，使用“显示更多”继续加载。
6. 选少量文档，选择 Markdown 并开始。确认本次任务总数等于选择数，只有选中文档产生下载，目录层级和标题命名保持原逻辑。进度区应分别显示成功、失败、处理中和待处理数。
7. 任务运行时修改选择草稿，确认任务范围不变。暂停后新建按钮与刷新按钮仍禁用。修改设置页输出目录后继续原任务，原任务仍使用开始时的目录及格式。
8. 关闭弹窗和选择页，稍后重新打开，确认后台任务继续存在。暂停任务后，在扩展管理页重新加载扩展，打开选择页并继续。对重启前的处理中项应显示结果待确认及重试可能产生副本的提示，不能直接计为成功。
9. 在测试任务中临时断网制造失败，恢复网络后点击“重试失败”。确认只重试原任务失败项，成功项不再请求，任务的格式、目录和文档范围不变。检查失败也计入已处理进度。
10. 同一选择完成后换一种格式再次开始，确认创建新任务，已成功文档也重新导出。再回弹窗使用“全量导出”，确认范围为完整目录。逐一验收 Markdown、OPML、FreeMind、HTML、Word、JSON 和 PDF。

当前“成功”仍表示原下载接口接受了下载创建请求。最终文件完成状态、实际文件名和内容需同时检查浏览器下载记录及本地文件；这些确认机制属于里程碑 3。已经提交给浏览器的旧下载不会因任务重置而自动撤销。

## 无账号的合成页面预览

运行 `node tests/preview-server.mjs`，访问 `http://127.0.0.1:8766/preview`。

- 仅绑定本机回环地址，使用合成目录、合成正文和模拟下载，不请求真实幕布接口。
- 目录包含 3,504 篇合成文档，可检查懒加载、长标题与不可信 HTML 文本展示。
- “B 文档”默认模拟失败，点击顶部“测试：允许失败文档重试”后可验证失败重试。
- 选择草稿使用预览专用 localStorage 键；真实扩展仍由后台 `chrome.storage.local` 管理。
- `/popup-preview` 可检查弹窗布局和入口。预览不模拟跨标签页共享 Service Worker，不能代替真实 Chrome 的后台生命周期验收。
- 验证完成后使用 Ctrl+C 停止本地服务器。
